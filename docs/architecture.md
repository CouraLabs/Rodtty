# Source layout

Rodtty is one crate. The library holds the platform-neutral core. `src/desktop` holds the Rune desktop app, which is compiled only with the `desktop` feature.

## Core library (`src/`)

| Module | Responsibility |
|---|---|
| `config` | Settings JSON: preferences, defaults, validation, and the startup folder |
| `session` | One terminal session: its PTY, Brush shell process, and screen state |
| `profile` | A session's environment: bundled-command launchers, `PATH`, and the startup script |
| `prompt` | Prompt styles and the shell hook that draws them |
| `files` | Text documents, the explorer tree listing, file search, file operations, and removal |
| `git` | Repository status and diffs |
| `work` | The background file worker (jobs and events) and saved workspace layout |
| `instance` | The single-instance lock and the reopen hand-off |
| `bin/shell.rs`, `bin/probe.rs` | `rodtty-shell`, the session shell and command launcher, and `rodtty-probe`, the PTY probe without a UI |

## Vendored crates (`vendor/`)

- `vendor/brush`: Brush, the Bash-compatible shell that `rodtty-shell` runs. It is its own Cargo workspace; `RODTTY-PATCH.md` lists every change from upstream, and `cargo test --manifest-path vendor/brush/Cargo.toml -p <crate>` runs its tests.
- `vendor/rune`, `vendor/rune-kit`: the UI toolkit, with Rodtty's patches recorded beside them.
- `vendor/trash`, `vendor/vte`: patched dependencies.

## Desktop app (`src/desktop/`)

`desktop.rs` declares the modules, runs the app (`run`), and wires its event loop (`setup`, `poll`). All app state lives in one `State` struct (`state.rs`). Each feature adds its own `impl State` block.

Each feature separates **model** code, which changes `State` and never builds UI, from **view** code: functions shaped `fn(&State, &Appearance, …) -> El` that only build UI and attach handlers. The handlers call model methods.

| Folder | Model | View |
|---|---|---|
| `ui/` | none | Reusable components: `button`, `icon_button`, `text_field`, `tab_pill`, `tab_indicator`, `tab_label` |
| `window/` | `palette.rs` (command palette state) | Root `view`, header, footer, workspace menu, custom `frame` |
| `terminal/` | `keys.rs` (key encoding), `search.rs`, `clipboard.rs` | `view.rs` (cell grid), `tabs.rs` (tab strip), `palette.rs` (cell colors) |
| `explorer/` | `model.rs` (tree, navigation, follow), `operations.rs`, `removal.rs` | `view.rs` (pane, root controls, menu), `icons.rs` |
| `editor/` | `model.rs` (open, save, reload, find) | `view.rs` (document content), `tab_strip.rs`, `status.rs` (status line), `dialog.rs` (file prompts) |
| `workspace/` | `workspace.rs` (types), `persistence.rs`, `poll.rs` (per-frame steps), `events.rs` (worker events) | `layout.rs` (pane visibility and body) |
| `settings/` | `model.rs` (open, reload, restore defaults), `catalog.rs` (the settings list) | `layout.rs` (page, tab strip, rows), `controls.rs` (shared controls), and one file per settings tab |
| `search/` | `search.rs` (search across files and terminals) | `view.rs` (field, results, footer) |
| `actions/` | `actions.rs` (`AppAction`), `registry.rs` (commands), `dispatch.rs` | none |
| `qualification/` | Preview scenes (`--scene`), demo fixtures, and the native checks behind the `--*-check` flags | none |

Modules shared by every feature stay at the top of `src/desktop/`:
- `appearance` (palettes and semantic colors)
- `fonts`
- `motion`
- `shortcuts`
- `tabs` (shared tab dragging)
- `autosave`
- `restoration` (cold-start restore)
- `input` (app-wide key handling)

## Conventions

- **Visibility:** items shared across feature folders are `pub(crate)`. Items used only inside a folder are `pub(super)` or private. Each module root re-exports its view functions (`pub(crate) use view::*;`), so other features call them by name.
- **Tests:** a module's tests live beside it. Short test modules stay inline; longer ones go in `<module>/tests.rs`. Shared UI test helpers (`runtime_for`, `press`, …) live in `src/desktop/tests.rs`.
- **Assets:** embed with `asset_bytes!` and `asset_str!`, which take paths relative to `assets/`. Moving a source file then never breaks its includes.
- **Generated code:** `explorer/icon_catalog.rs` is generated by `scripts/import-icons.mjs`. Don't edit it by hand.
- **Before adding a component:** check `ui/` first. Build a new shared component only once a second caller needs it.
